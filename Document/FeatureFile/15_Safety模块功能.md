# Safety 模块功能

- 顶层模块：`MultiStation.Safety`
- 子模块：`.Interlock`
- 合并依据：唯一必须独立故障域的模块，不能与其他模块合并
- 功能编号段：F-SAF-01 ~ F-SAF-05

## 一、功能清单

| 编号 | 功能 | 说明 | 状态 |
|---|---|---|---|
| F-SAF-01 | 急停 | 硬件回路切断动力，软件读取状态位并处置 | 规划 |
| F-SAF-02 | 安全联锁 | 安全门、光栅、治具到位联锁 | 规划 |
| F-SAF-03 | 门禁 | 权限门开启条件与运行模式互锁 | 规划 |
| F-SAF-04 | 安全状态广播 | 状态位变化通过直通回调与事件通知全模块 | 规划 |
| F-SAF-05 | 停机处置 | 停投料、断输出、锁定界面、记录事件 | 规划 |

## 二、关键规则

| 规则 | 内容 |
|---|---|
| 硬件优先 | 急停与断输出由安全继电器直接完成，软件仅为附加措施 |
| 不排队 | 安全状态位读取周期 ≤ 20ms，不经普通消息队列 |
| 不可软件复位 | 安全状态只能硬件恢复后复位，软件任何角色不可清除 |
| 幂等处置 | 停机处置流程幂等，单步失败仍继续后续安全动作 |
| 独立故障域 | 不依赖 Core 总线可用性，兜底路径独立 |

## 三、验收标准

| 编号 | 场景 | 期望 |
|---|---|---|
| A-01 | 按下急停 | 动力立即切断，界面显示安全状态，重启后仍需硬件复位 |
| A-02 | 运行中打开安全门 | 停止动作并断输出，报警等级为安全 |
| A-03 | 消息总线阻塞 | 安全状态位仍能读取与处置 |
| A-04 | 停机处置中某步失败 | 继续执行后续安全动作，最终记录完整清单 |
| A-05 | 操作员尝试软件复位 | 拒绝，提示需硬件恢复 |
