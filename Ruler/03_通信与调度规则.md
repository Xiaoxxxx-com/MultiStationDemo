# 通信与调度规则

适用范围：Core 总线和全部模块的跨模块通信。

## 一、消息语义

| 编号 | 规则 | 说明 | 级别 |
|---|---|---|---|
| C-01 | 只允许四类消息语义 | Command（点对点需回复）、Query（取快照）、Event（广播）、Stream（控制帧） | 阻断 |
| C-02 | 需要等结果用 Command / Query，通知用 Event | 两者不得混用，不得新增第五种语义 | 强制 |
| C-03 | Stream 只承载控制帧 | 图像、波形、高频测量值必须走数据面句柄 | 阻断 |
| C-04 | 消息体软限 4KB、硬限 64KB | 超硬限直接拒绝并记 `MSG_TOO_LARGE`；超过 4KB 应改走 `BufferHandle` | 阻断 |

## 二、优先级

| 编号 | 规则 | 说明 | 级别 |
|---|---|---|---|
| C-05 | 优先级只有三级 | Control / Normal / Background，禁止裸整数 | 阻断 |
| C-06 | 默认值固定 | Command=Control，Query/Event=Normal，Stream=Background | 强制 |
| C-07 | Control 严格优先 | 不被任何级别插队，配额与老化均不作用于 Control | 阻断 |
| C-08 | 老化只作用于 Normal / Background | 等待超 500ms 晋升一级，最多一级 | 强制 |
| C-09 | 配额公平不越级 | 每 8 条 Normal 放行 1 条 Background，Control 不参与 | 强制 |
| C-10 | 禁止优先级膨胀 | 普通事件不得标 Control；评审按优先级分布检查 | 强制 |
| C-11 | 优先级只改出队顺序 | 非抢占，不中断处理中的消息；需要中断走取消命令 | 强制 |

## 三、投递

| 编号 | 规则 | 说明 | 级别 |
|---|---|---|---|
| C-12 | 投递一律非阻塞 | 返回 `Accepted / Rejected / Replaced / Coalesced`，调用方必须检查结果 | 阻断 |
| C-13 | 执行循环内禁止阻塞等待 | 模块执行循环内不得调用任何阻塞 API，含 `RequestAsync` | 阻断 |
| C-14 | Event 每订阅者独立队列 | 发布者不被慢订阅者阻塞；Background 事件按业务键合并 | 阻断 |
| C-15 | 满时策略按级别固定 | Control 拒绝不丢；Normal 合并或拒绝；Background 替换最旧 | 强制 |
| C-16 | 链路跳数上限 8 | 超过即拒绝并告警，作为环等待的运行期兜底 | 阻断 |

## 四、请求与超时

| 编号 | 规则 | 说明 | 级别 |
|---|---|---|---|
| C-17 | 超时不等于未执行 | 超时只解除请求方等待，不代表被调方未执行 | 阻断 |
| C-18 | 超时必须传播取消 | Core 向被调方投递 `Cancel(correlationId)` | 阻断 |
| C-19 | 被调方必须回最终状态 | 回 `Cancelled`（未执行）或 `CompletedLate`（已执行，附结果） | 阻断 |
| C-20 | 迟到回复不得静默丢弃 | 按 correlationId 归入最终状态并记录 | 强制 |
| C-21 | 涉及副作用的命令必须带幂等键 | 幂等键持久化，重放返回首次结果 | 阻断 |
| C-22 | 超时默认值 | Control 3s、Normal 2s、Background 500ms 或不等待 | 强制 |

## 五、身份与审计

| 编号 | 规则 | 说明 | 级别 |
|---|---|---|---|
| C-23 | source 由 Core 覆盖 | 路由时用注册表真实 ModuleId 覆盖，不信任入参 | 阻断 |
| C-24 | actor 与 principalRole 必填 | 操作者或上层系统标识，缺失按 System 记录 | 强制 |
| C-25 | 低权限模块不得发 Control | 越权一律拒绝并记 `AUDIT_DENIED` | 阻断 |
| C-26 | 关键命令写审计流 | 谁、何时、对哪个模块下发什么、结果如何 | 强制 |

## 六、顺序与一致性

| 编号 | 规则 | 说明 | 级别 |
|---|---|---|---|
| C-27 | 同流同优先级 | 同一 TraceId 内消息使用同一优先级 | 强制 |
| C-28 | 按 sequence 窗口重排 | 模块内按 (TraceId, sequence) 以窗口 16 重排 | 强制 |
| C-29 | 不依赖跨流顺序 | 不同工件、不同工位可任意交错 | 强制 |
| C-30 | 状态携带 StateVersion | Event 与 Query 快照同源携带，跳号即 resync | 强制 |

## 七、执行约束

| 编号 | 规则 | 说明 | 级别 |
|---|---|---|---|
| C-31 | 单条消息处理 ≤ 50ms | 超过部分必须下沉作业池，完成后以消息回投 | 阻断 |
| C-32 | 慢操作走作业池 | 模块循环只做状态迁移，不直接做设备 IO 与库写入 | 强制 |
| C-33 | StopAsync 5s 超时 | 超时强制取消并记录未处理消息数与死信清单 | 强制 |
| C-34 | 停机顺序固定 | 停投料 → 排空 Control/Normal → 停设备 → 冲刷 Background → 退出 | 强制 |

## 八、配置

| 编号 | 规则 | 说明 | 级别 |
|---|---|---|---|
| C-35 | 优先级与超时配置启动期强校验 | 缺键直接抛异常，禁止静默降级 | 阻断 |
| C-36 | 主题必须强类型 | 用 `Topics` 常量，禁止裸字符串 | 强制 |

## 九、代码示例

```csharp
public enum MessagePriority { Control = 1, Normal = 2, Background = 3 }

public enum DeliveryResult { Accepted, Rejected, Replaced, Coalesced }

public interface IMessageBus
{
    ValueTask<DeliveryResult> SendAsync<T>(
        string target, T body, MessagePriority priority, CancellationToken ct) where T : class;

    ValueTask<DeliveryResult> PublishAsync<T>(
        string topic, T body, MessagePriority priority, CancellationToken ct) where T : class;

    // 只允许在非执行循环线程调用
    Task<RequestOutcome> RequestAsync<T>(
        string target, T body, MessagePriority priority, TimeSpan? timeout, CancellationToken ct) where T : class;

    ValueTask<RequestOutcome?> QueryOutcomeAsync(Guid correlationId, CancellationToken ct);
}
```

```csharp
// 正确：检查投递结果
var result = await bus.SendAsync(Targets.Device("plc_main"), cmd, MessagePriority.Control, ct);
if (result == DeliveryResult.Rejected)
    await ReplyFailedAsync(message, ErrorCodes.BusRejected, ct);

// 错误：忽略投递结果
await bus.SendAsync(Targets.Device("plc_main"), cmd, MessagePriority.Control, ct);
```
