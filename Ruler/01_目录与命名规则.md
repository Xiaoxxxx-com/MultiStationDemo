# 目录与命名规则

适用范围：`src` 下全部代码。规则同时约束物理目录、命名空间、程序集与类型命名，四者必须一致。

## 一、顶层模块（7 个，固定）

| 顶层模块 | 职责 | 合并依据 |
|---|---|---|
| `MultiStation.Test` | 调度分发、在制品、完工判定、结果判定、工位序列执行、状态机、量测算法规程 | 判定与调度服务同一件事：决定工件往哪走、算不算通过；算法与步骤强绑定 |
| `MultiStation.Error` | 看门狗、启动自检、降级决策、报警管理 | 四件事都在回答同一个问题：系统还正不正常 |
| `MultiStation.Platform` | 契约、内核、配置中心、配方与版本、序列定义、权限与审计、组合根、仿真 | 低频写、高频读的静态数据，一个加载缓存即可服务全部 |
| `MultiStation.Device` | PLC、相机、仪表、机器人统一会话 | 合并依据是独占外设，不可再拆 |
| `MultiStation.Data` | 结果落库、步骤明细、遥测日志、死信归档、报表与 SPC 查询 | 全是写盘与查盘，共用一套库与一套迁移 |
| `MultiStation.Safety` | 急停、联锁、门禁 | 唯一必须独立故障域的模块，不能合 |
| `MultiStation.Ui` | 看板、序列编辑器、配方界面、报表、报警中心、桌面外壳 | 全部面向人机交互 |

## 二、目录结构

| 编号 | 规则 | 说明 | 违反判定 | 级别 |
|---|---|---|---|---|
| R-01 | src 下第一层只允许上述 7 个顶层模块 | 名称固定为 `Test` / `Error` / `Platform` / `Device` / `Data` / `Safety` / `Ui`，统一 `MultiStation.` 前缀 | 出现第 8 个顶层目录 | 阻断 |
| R-01a | 模块名必须紧跟 `MultiStation.`，禁止插入中间段 | 正确 `MultiStation.Test`；错误 `MultiStation.Modules.Test`、`MultiStation.Domain.Test`、`MultiStation.Services.Test` | 出现 `.Modules`、`.Domain`、`.Services` 等中间段 | 阻断 |
| R-01b | 同一职责不得拆成多个顶层模块 | 能归入统一名称的必须合并为一个大模块，能力以子模块存在；报警不得单独成模块，结果与日志不得分家 | 出现功能重叠的顶层模块 | 阻断 |
| R-02 | 子模块目录 = 顶层模块名 + "." + 子模块名 | 如 `MultiStation.Test.Station`、`MultiStation.Data.Persistence` | 使用下划线、连字符、空格，或省略顶层前缀 | 阻断 |
| R-03 | 孙模块目录 = 顶层模块名 + "." + 子模块名 + "." + 孙模块名 | 逐层追加，如 `MultiStation.Test.Parts.Flow`、`MultiStation.Device.Adapters.Modbus` | 跳级命名 | 阻断 |
| R-04 | 命名只允许字母、数字与点 | 层级名不得使用 Utils / Common / Helper / Base 等泛化词 | 出现非法字符或泛化层级名 | 阻断 |
| R-08 | 目录深度不超过 4 层 | `src/顶层模块/子模块/孙模块` | 出现 `src/A/B/C/D/E` | 强制 |

## 三、命名空间与程序集

| 编号 | 规则 | 说明 | 违反判定 | 级别 |
|---|---|---|---|---|
| R-05 | 命名空间 = 目录名本身 | 顶层模块根目录下的文件命名空间即模块名；子模块文件的命名空间即子模块目录名（点分隔），不与程序集名重复拼接 | 目录与 namespace 不一致 | 阻断 |
| R-06 | 一个顶层模块可含多个程序集 | 每个子模块一个 csproj，程序集名 = 子模块目录名；子模块的孙目录不单独成程序集 | 孙目录拆出独立 csproj | 强制 |

## 四、类型命名

| 编号 | 规则 | 说明 | 示例 | 级别 |
|---|---|---|---|---|
| R-07 | 总类 = 模块名去前缀 + Module | 模块总类唯一，外部唯一可引用类型 | `TestModule`、`DeviceModule`、`ErrorModule` | 强制 |
| R-07a | 部分类 = 总类名 + 职责 + Part | 每个 Part 只负责一个部分 | `TestFlowControlPart`、`DeviceHealthPart` | 强制 |
| R-07b | 消息类型 = 域 + 动作 + Command / Event | 语义与类型名一致 | `TestStepResultEvent` | 强制 |
| R-07c | 主题常量集中在 Topics 类 | 禁止裸字符串 topic | `Topics.Test.StepResult` | 强制 |

命名示例对照：

| 层级 | 目录 | 命名空间 | 程序集 | 典型类型 |
|---|---|---|---|---|
| 顶层模块 | `src/MultiStation.Test` | `MultiStation.Test` | —（容器，可含多个程序集） | — |
| 子模块 | `src/MultiStation.Test/MultiStation.Test.Station` | `MultiStation.Test.Station` | `MultiStation.Test.Station.dll` | `StationModule` |
| 孙模块 | `.../MultiStation.Test.Parts.Flow` | `MultiStation.Test.Parts.Flow` | `MultiStation.Test.dll` | `FlowControlPart` |
| 基础设施 | `src/MultiStation.Platform/MultiStation.Platform.Core` | `MultiStation.Platform.Core` | `MultiStation.Platform.Core.dll` | `Dispatcher` |

## 五、引用与流程

| 编号 | 规则 | 说明 | 违反判定 | 级别 |
|---|---|---|---|---|
| R-09 | 先建目录再写代码 | 目录名与 `ModuleDescriptor.ModuleId` 的域段一致 | 代码先于目录存在 | 强制 |
| R-10 | 业务模块之间零引用 | `Test`、`Device`、`Safety`、`Error`、`Ui` 之间禁止 project reference，只允许引用 `MultiStation.Platform.*` 与 `MultiStation.Data.*`；跨模块交互走 Core 消息总线 | 出现业务模块间引用 | 阻断 |
| R-11 | 迁移期旧目录逐步并入 | 已完成：原 16 个平铺模块 → 7 个顶层模块；`Core/Devices` → `Platform.Core.Devices`；`Persistence`+`Telemetry` → `Data.*`；`Dispatch`+`Station`+`Test` → `Test.*`；`Supervisor` → `Error` | 新旧目录长期并存 | 建议 |
| R-12 | 规则由工具强制 | Roslyn 分析器校验命名与引用，CI 脚本校验目录结构 | 仅靠人工评审 | 强制 |

## 七、新增功能落地顺序

1. 判断职责归属，优先并入已有 7 个顶层模块，不新开顶层模块
2. 在对应顶层模块下建子模块目录，如 `src/MultiStation.Test/MultiStation.Test.Alarm`
3. 建 csproj，程序集名与子模块目录同名
4. 实现 `XxxModule`（继承 `ModuleBase`）与各部分 Part
5. 在 Host 组合根注册，并在模块清单登记
6. 跑目录校验与分析器，全绿后提交

确需新增第 8 个顶层模块时，必须评审并在本节与校验脚本中同步更新白名单。

## 八、校验实现

```
// CI 目录校验
var allowedTopModules = new[]
{
    "MultiStation.Test", "MultiStation.Error", "MultiStation.Platform",
    "MultiStation.Device", "MultiStation.Data", "MultiStation.Safety", "MultiStation.Ui"
};
var forbiddenMiddle = new[] { "Modules", "Domain", "Service", "Services", "Component", "Layer" };

foreach (var dir in Directory.GetDirectories("src"))
{
    var name = Path.GetFileName(dir);
    Assert(allowedTopModules.Contains(name), "R-01");

    foreach (var sub in Directory.GetDirectories(dir))
    {
        var subName = Path.GetFileName(sub);
        Assert(subName.StartsWith(name + "."), "R-02");

        var tail = subName.Substring(name.Length + 1);
        Assert(!forbiddenMiddle.Contains(tail.Split('.')[0]), "R-01a");
        Assert(!subName.Contains("_"), "R-04");
    }
}
```
