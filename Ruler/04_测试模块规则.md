# 测试模块规则

适用范围：`MultiStation.Test` 及全部测试脚本（PCTest 序列）。

## 一、五序列生命周期

| 编号 | 规则 | 说明 | 级别 |
|---|---|---|---|
| T-01 | Start 每进程只执行一次 | 程序启动时校验仪器在线（电源、CAN、PLC、扫码、MES），任一项离线则拒绝进入自动模式 | 阻断 |
| T-02 | End 每进程只执行一次 | 程序关闭时关输出并断开会话；单台失败继续其余，输出未关闭清单并告警 | 阻断 |
| T-03 | Pre / Main / Post 每件各执行一次 | 不存在「跳过 Pre 直接测」的路径 | 阻断 |
| T-04 | Post 为必达收尾 | 无论 Pre / Main 通过、失败、超时、取消、异常，Post 都必须执行且只执行一次 | 阻断 |
| T-05 | Pre 或 Main 失败立即转 Post | 当前序列剩余步骤全部跳过，Main 一步不执行（Pre 失败时） | 阻断 |
| T-06 | Post 内部失败不改变判定 | best effort 执行全部步骤，记独立错误码，阻止下一件启动 | 强制 |

五序列职责：

| 序列 | 职责 | 失败后 |
|---|---|---|
| Start | 确认仪器都在线，能测 | 拒绝自动模式，仅允许诊断 |
| Pre | 把仪器恢复到已知初始态 | 跳 Post，判 NG |
| Main | 跑主要测试项 | 跳 Post，判 NG |
| Post | 关输出、复位，绝不残留 | 继续执行，仅告警 |
| End | 关会话，释放仪器 | 继续执行，列清单告警 |

## 二、阶段编排

| 约束 | 说明 |
|---|---|
| Post 由 `StageRunnerPart` 的 `finally` 调用 | 使用独立取消令牌，即使主流程被取消仍执行 |
| 脚本的 FailEnd / End 只结束当前序列 | 不得影响 Post 的必达性 |
| Post 执行期间禁止启动下一件 Pre | 保证单件串行与设备状态可预期 |
| Post 不允许断点续测 | 续测只允许从 Pre 或 Main 的断点继续 |

```csharp
await RunAsync(Trigger, ct);
var verdict = Verdict.Pass;
try
{
    verdict = await RunAsync(Pre, ct);
    if (verdict == Verdict.Pass)
        verdict = await RunAsync(Main, ct);
}
catch (OperationCanceledException) { verdict = Verdict.Aborted; }
catch (Exception) { verdict = Verdict.Error; }
finally
{
    // 独立令牌：即使主流程被取消，Post 仍要执行
    await RunAsync(Post, CancellationToken.None);
}
await PersistAsync(verdict, ct);
```

## 三、脚本校验规则

校验在 `sequence.load` 时执行一次。V-01 ~ V-13 任一失败则拒绝加载；V-14 / V-15 只告警。

| 编号 | 规则 | 级别 |
|---|---|---|
| V-01 | 编号在序列内唯一（段落标记除外） | 阻断 |
| V-02 | 跳转目标存在且在同一序列内，禁止跨序列跳转 | 阻断 |
| V-03 | Ternary 两个目标均存在，`Pass?A:B` 语法正确 | 阻断 |
| V-04 | While 带超时且与「测试超时时间」一致 | 阻断 |
| V-05 | SwitchCase 含默认分支 `*`，语法 `@VAR:值:目标;…` | 阻断 |
| V-06 | Min ≤ Max；Test 类阈值不得为空 | 阻断 |
| V-07 | 设备在设备注册表中存在 | 阻断 |
| V-08 | DSL 首个键为已知 COM/OP，必填键齐全 | 阻断 |
| V-09 | 超时 > 0，重试次数 0~3 | 阻断 |
| V-10 | 占位符引用的变量已声明 | 阻断 |
| V-11 | FailEnd / End 之后同序列步骤不可达 | 告警 |
| V-12 | 启用=F 的步骤被跳转引用 | 告警 |
| V-13 | Post 为空或缺少「关输出」类步骤 | 阻断 |
| V-14 | End 缺少会话关闭步骤 | 告警 |
| V-15 | Start 缺少仪器连通性检查 | 告警 |

V-13 ~ V-15 是安全底线类校验，缺失即视为脚本缺陷。

## 四、步骤与流程

| 步骤类型 | 语义 | 下发设备 | 参与判定 |
|---|---|---|---|
| TestProject | 段落标记，用于分组与界面折叠 | 否 | 否 |
| Title | 标题行，仅展示 | 否 | 否 |
| Test | 执行并判定，产出测量值 | 是 | 是 |
| Action | 只执行不判定 | 是 | 否 |
| Wait | 延时或分流 | 否 | 否 |

| 流程原语 | 语法 | 语义 |
|---|---|---|
| Ternary | `Pass?目标A:目标B` | 通过跳 A，失败跳 B |
| PassGoto | `目标编号` | 成功后跳转 |
| While(60s) | `Pass` | 轮询直到通过或超时 |
| SwitchCase | `@VAR:值:目标;*:默认` | 按变量值多路分流 |
| FailEnd | 空 | 立即结束当前序列并判 NG |
| End | 空 | 正常结束当前序列 |
| PostDelay | 毫秒 | 本步完成后延时（附加动作） |

## 五、设备与判定

| 规则 | 说明 | 级别 |
|---|---|---|
| 主流水对同一设备串行 | 上一条命令未返回不得发下一条 | 阻断 |
| Monitor 只允许读命令 | 不得抢占 Control，按来源公平调度 | 阻断 |
| 连续点位合并批命令 | 如 R10010.0~R10010.7 合并为一条 `executeBatch` | 强制 |
| 判定引擎只产出 Pass / Fail | 失败取向由脚本与序列配置决定，不写进适配器 | 强制 |
| Action / Wait 不参与判定 | 只要求执行成功 | 强制 |

## 六、结果与追溯

| 层级 | 必含字段 |
|---|---|
| StepResult | code、group、verdict、durationMs、actual、min、max、equal、errorCode、retryCount |
| StageResult | stageId、role、verdict、durationMs、failedStep、skipCount、mustRunOnFailure |
| UnitResult | workItemId、carrierId、recipe、verdict、cycleMs、failCode、stages |
| MachineResult | startSelfCheck、endShutdown、unclosedDevices |
| Checkpoint | unitKey、stageId、stepIndex、inputSnapshot、committed |

| 规则 | 说明 | 级别 |
|---|---|---|
| checkpoint 与结果同事务提交 | 避免「结果写了但进度没写」 | 阻断 |
| 失败必须记录跳转点与未执行步骤数 | 便于还原失败路径 | 强制 |
| 禁用步骤记 Skipped | 不计入失败率，但保留在追溯链 | 强制 |
| End 未关闭清单写入 MachineResult | 下次启动时展示 | 强制 |
